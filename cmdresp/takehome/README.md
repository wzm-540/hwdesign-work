# Max-affine command-response mini-project

For every scalar sample, compute the maximum of up to 16 configurable affine
functions, using signed 16-bit inputs/outputs with eight fractional bits.
The reviewed requirements are in [prompt.md](prompt.md); the final measured
results and all seven required report sections are in [results.md](results.md).

## Files

| File | Purpose |
| --- | --- |
| `model.py` | Exact integer arithmetic and stream protocol model |
| `verify_model.py` | Independent NumPy reference, hand checks, scenario generation |
| `maxaffine.hpp`, `maxaffine.cpp` | Synthesizable kernel |
| `tb_maxaffine.cpp` | Same testbench for C simulation and RTL co-simulation |
| `run.tcl`, `build.py` | Vitis driver and reproducible build |
| `analyze.py` | Compare results and measure actual RTL handshakes |
| `extract_waveform.py` | Waveflow snapshot replay for VCD export only |
| `package.py` | Clean source/evidence ZIP for moving to your own GitHub repository |
| `vectors/` | Committed stimuli and expected words/status for every activation |
| `evidence/` | Simulation results, logs, synthesis report, trace and measurements |

## Reproduce

Use a Python environment with `waveflow`, `numpy` and `vcdvcd`, and put
`vitis-run` on PATH. The recorded run used the course `.venv` and Vitis 2026.1.
Run from this folder (replace the Python path for your installation):

```bash
/home/zw5112/hwdesign/.venv/bin/python build.py --through model
/home/zw5112/hwdesign/.venv/bin/python build.py --through csim
/home/zw5112/hwdesign/.venv/bin/python build.py --through csynth
/home/zw5112/hwdesign/.venv/bin/python build.py --through cosim
/home/zw5112/hwdesign/.venv/bin/python build.py --through trace
/home/zw5112/hwdesign/.venv/bin/python analyze.py
```

Alternatively `build.py` with no arguments runs all stages. Stages already
marked complete are skipped; use `--rerun` after changing kernel, testbench,
protocol or tool settings. Co-simulation is one invocation covering the whole
scenario suite. A working university Vitis license connection is required.
Waveform extraction replays the existing XSIM snapshot without invoking
cosim_design again; the reason and correction are recorded in Run History.
`include/` is regenerated from installed Waveflow; it is not hand-maintained.

For bash, activation is `source /home/zw5112/hwdesign/.venv/bin/activate`;
for csh/tcsh it is `source /home/zw5112/hwdesign/.venv/bin/activate.csh`.
Calling the environment's Python directly has the same interpreter/package
selection effect. Activation alone does not install Vitis or grant a license.

## Reference and tool choices

The design follows the host-activated Waveflow
[stream_inband example](https://sdrangan.github.io/waveflow/docs/examples/stream_inband/).
The exact upstream files consulted are preserved under `evidence/reference/`.
Its `run.tcl` selects `xc7z020clg484-1` and a 10 ns requested clock; those are
the settings used here. The older course demo uses another package variant
and was consulted only for introductory stream helper usage. No Waveflow MCP
was connected in this session: public upstream source and the installed
Waveflow Python package were used directly. Stream support is generated by
Waveflow's `StreamUtilsStep`; protocol serialization is written explicitly.
Configuration persistence within one activation follows the course prompt.

## Submission

Put this entire folder, including its cited evidence, at
`cmdresp/takehome/` in **your own public** `hwdesign-work` GitHub repository.
Exclude the local `maxaffine_proj/`, `include/`, caches and grader-export JSON.
Keep `evidence/` and `vectors/`. Some parent course ignore rules ignore CSV
alternatives such as `.rpt`/`.json`; evidence here uses `.txt`/`.csv` and a
compressed trace, so the committed report remains independently inspectable.

1. Part 3 of the LLM grader receives the full text of `prompt.md`.
2. Part 4 receives the public folder URL, for example
   `https://github.com/YOUR_NAME/hwdesign-work/tree/main/cmdresp/takehome`.
3. Set the grader timeout to at least 100 seconds and check its feedback.
4. Download the submission ZIP from the LLM grader Dashboard and upload that
   ZIP to Gradescope. The source-code archive is for GitHub transfer, not a
   replacement for the grader's own Gradescope submission ZIP.

The local repository's `origin` belongs to the instructor. Do not push student
work there; use your own public repository for Part 4.

To prepare a clean transfer archive, run `python package.py`. It creates
`../takehome_submission.zip`, with paths starting at `cmdresp/takehome/`.
Unzip it into the root of your own `hwdesign-work` clone and commit/push that
folder. The ZIP deliberately excludes the tool project and generated headers.
